## Findings

1. `web/src/pages/admin/PlatformSettingsPage.tsx:107–112` and `:125–127`
   (`orgRowBusy` / `orgRowError`, `tournamentRowBusy` / `tournamentRowError` are
   page-level), fed into every row at `:482–483` and `:558–559` and rendered only
   at `PlatformFeeEditor.tsx:241` → **#3, #15** — a refused save is announced
   inside whichever editor happens to be open at the moment the response lands,
   so the one failure a money setting must never hide lands in the wrong place or
   nowhere at all. Two reproductions, both provoked live (PATCH to
   `/rest/v1/organizations` delayed 3 s, then 406 / `PGRST116`):

   - **Nothing at all.** Tap `Save fee`, then tap the row's `Close` (which stays
     enabled through the save, `:721–728`) before the response lands. The write
     is refused; the editor is gone, so the error panel never mounts. The screen
     shows no error, no confirmation and an unchanged row — after an explicit
     Save, that silence reads as success. Verified: page text after settling
     contained neither "wasn't saved" nor "Saved just now".
   - **The wrong organizer.** Tap `Save fee` on Granite State, then open any
     other row before the response lands. The refusal renders under *North
     Country Pickleball & Racquet Sports Cooperative of the Upper Valley* — an
     organizer whose fee was never touched — telling the reader their fee wasn't
     saved (shot `390-save-error-lands-on-the-wrong-row.jpg`). Item 3 asks for
     the error "inline by the cause"; this is inline by the wrong cause.

   The same shared state also makes every other row's button read `Saving…` while
   one row saves (`saving={orgRowBusy}` at `:482`, `:558`). Item 15 is the one
   this fails hardest: *"we can never leave the person who is creating an event
   with the feeling that it happened when it didn't."*

   **Fix:** make the failure belong to the row that caused it, exactly as the
   success already does — hold `orgErrorId` / `tournamentErrorId` beside the
   existing `orgSavedId` (`:112`) and render the danger panel on the row at
   `:731–735`, outside the `open` guard, so it survives the editor closing and
   can never attach to a different row. (Disabling `Close` while `saving` closes
   only the first reproduction, not the second.)
