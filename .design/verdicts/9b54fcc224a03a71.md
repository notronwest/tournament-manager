## The probes, answered

- **Can the seen-marking fire on a panel the operator is not looking at?** No
  via a tab: `PlatformSettingsPage.tsx:517`, `:557`, `:614` render each panel
  behind `tab === …`, so an inactive tab's `ResultPanel` is unmounted rather
  than hidden, and `onShown` cannot run. Measured: with a default refusal and
  an organizer refusal both live, `/wasn't saved/` was absent from the whole
  document while the operator sat on Tournaments.
- **Can it fire on a panel rendered off-screen?** Not in a way that matters.
  `onShown` fires in the same ref callback that spends the pull, and the pull
  key is unique per attempt for the life of the page, so the first mount of any
  refusal both marks it seen and brings it into view. Measured on the longest
  case available — the last row of the organizer list, the panel the last thing
  in the document — 711–795 in an 844 viewport.
- **Does "clear only what was seen" strand a refusal that cannot be dismissed?**
  It can leave one alive and invisible, but never undismissable: a row toggle or
  the next save at that level clears it, and re-tapping the active tab clears a
  read one. See the first note below for the invisible case, which this diff
  did not create.
- **Do the three levels collide now the counter is page-wide?** No — see
  change 2 above. `attemptSeq` is strictly increasing for the page load and the
  keys are prefixed per mount point (`default-err-N`, `org-<id>-err-N`,
  `org-<id>-row-err-N`, `tournament-<id>-…`), so two refusals in one page load
  cannot share a key. `seenFailures` is per-mount, but so is the error state it
  guards, so the two reset together.
