## Notes (non-blocking)

- **The scroll fires on mounts the reader did not cause, and the standard has
  no number for that (D-0018).** Three reproductions, all at 390 × 844:
  (a) with the PATCH delayed 2.5 s, the operator scrolled to the foot of the
  organizer list (`scrollY` 712) while the save was in flight and the landing
  response **yanked the page back to 386** — a 326 px jump to a row they had
  left; (b) after saving White Mountain, typing "granite" into the organizer
  search and then clearing it re-mounted that row's panel and took the page from
  **0 to 361** while the caret was still in the search field
  (`390-orgs-search-filtered-before-clear.jpg` →
  `390-orgs-search-cleared-page-jumped-361px.jpg`); (c) leaving the Default tab
  and coming back moves it **0 → 90**. None of these breaches a numbered item —
  nothing is hidden, the focused field stays on screen, and the tab strip stays
  put — and CRITIC's rule is that a finding without a number is a note, so this
  does not block. It is still the sharpest remaining edge in the change: the
  panel should pull itself in only when it mounts *because this reader just
  saved*, e.g. a one-shot flag set in the save handler and consumed by the first
  mount, rather than on every mount of a panel whose state happens to be set.
  Worth a sentence in `CHECKLIST.md` either way — "motion the reader did not ask
  for" is now a thing this fleet can produce and no item describes it.
- **The Default tab's confirmation outlives the tab.** Switch away and back and
  the panel returns, undated. The remount re-seeds the fields from the saved
  value, so the claim is true when it reappears — which is why it is a note and
  not a repeat of the last verdict's third finding — but it is a confirmation
  for an action taken arbitrarily long ago.
- **The line that dates the save is 5 px below the fold.** After a default save
  the confirmation sits at 755/820 and *"Last saved just now by Tournament
  Director"* at **849/867** in an 844 viewport. The last verdict asked that the
  two stay in one viewport; they nearly do. `scrollMarginBlock: 24`
  (`PlatformFeeEditor.tsx:355`) is 30 px short of carrying both — a larger
  bottom margin would close it.
- **The refusal announces politely.** `ResultPanel` hard-codes `role="status"` /
  `aria-live="polite"` for both tones (`:349–350`), while this repo's other save
  errors use `role="alert"` (`RegistrationEditorModal.tsx:457`,
  `PlayerRegistrationsModal.tsx:79`). It is an improvement on the previous
  role-less div and the panel is visually unmissable, so not a floor breach —
  but the tone deserves `role="alert"` to match the repo's own convention.
- **A failed name lookup silently drops the attribution.** The re-resolve at
  `PlatformSettingsPage.tsx:284–291` sets `savedByName` to null when the
  `players` query returns nothing, so a transient failure of that second request
  removes the "by …" clause from a line that had one. One line of defence next
  time it is touched.
- Every standing note from the third, fourth and fifth verdicts is unchanged by
  this diff and still stands: the refusal cleared by touching any other row; the
  seventh local copy of the tile pattern awaiting a shared `ChoiceTile`;
  `inputStyle`'s 1.35:1 resting border; text loading lines rather than
  skeletons; the fleet-wide breadcrumb and wordmark sizes; raw hex at the call
  site; `orgRowError?.id === org.id` dereferencing on an id-less row; and #19b's
  tab-switch reading. None is this change's to carry.
