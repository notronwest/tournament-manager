## Notes (non-blocking)

- **The honesty of the rating refusal — the thing I was asked to judge — holds.** A child
  added to a skill-bounded bracket is refused *"no doubles self-rating on file"*, which names
  what is missing, and is sent to *"Pick someone else above, or a different event"*, which is
  a move that works. It does not claim a fix that does not exist and it does not circle back
  into the step that produced it. What it does not say is **who supplies the rating** —
  because nobody can: `/profile` carries a self-rating picker for the account holder and the
  My family rows carry a name, an age and a remove button only. That is the pre-existing gap
  being filed separately; the base commit's copy here was identical, so this change neither
  caused nor worsened it.
- **`refusedOnAge` is `.some()`, not "age is the only reason" — so a *mixed* refusal still
  routes to add-a-youth.** Verified live: with the juniors bracket given `3.0–4.0`, the
  parent's own panel reads *"You can't enter this event: no doubles self-rating on file;
  needs age 18 or under. Pick someone else above, or choose "Add a youth…" to enter a
  child."* Follow it and the child you create is refused for the rating. The errand is one
  hop longer than the loop the last verdict charged, and it still cannot complete. **Not
  charged**, because the only thing that makes it fail is the missing dependent-rating UI
  that is explicitly out of scope here, and the right fix is that UI rather than a gate that
  would hide the youth path from every skill-bounded juniors bracket forever. **The separate
  story should cover the entry points too** (this panel, the chooser option and the aged-out
  CTA on a skill-bounded bracket), not only the refusal wording.
- **Same shape, same conclusion, for gender.** `AddChildForm` collects first/last/dob and
  nothing can set a dependent's gender afterwards, so on a *men's or women's* age-capped
  bracket ("Boys 18 & Under") the aged-out CTA opens a path that ends in *"…can't enter this
  event: men's event"*. `refusedOnAge` is correctly false there, so the advice falls back to
  the plain copy and does not loop. Recorded so the dependent-profile story is scoped to
  gender as well as rating.
- **`youthCanEnterByAge` excludes `min_age === 18` exactly.** An 18+ bracket hides "Add a
  youth…", although an 18-year-old dependent would qualify (the guardian link requires an
  account-less player, not a minor). Defensible product line — recorded as the boundary that
  was chosen, not as a defect.

  amber `warnBg` `#fef6d6`, 12px regular, measured in the running page against the effective
